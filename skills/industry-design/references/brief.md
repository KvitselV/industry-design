# Brief

Ask only for what is still unknown. Put every question in one message. Do not design in that message.

Group them so the user can answer in a short block:

```text
Product
- What is it, in one sentence?
- Which industry or category should it be judged against?
- Who is it for?

Goal
- What is the one primary action? (trial, demo, buy, waitlist, download, activate, complete a task)
- What do they get?
- What must be understood on the first screen?
- What are the top objections?

Proof and brand
- Which logos, numbers, quotes, or guarantees are real and approved?
- Is there an existing site, font, color, voice, or component library?
- Any direction you want, or should the industry references decide?

Surface
- Landing page, app screen, flow, faux product demo, or a redesign of something that already exists?
- Web, iOS, or both? Does mobile come first?
- Where does traffic come from, if this is a campaign page?
```

Skip a group that the task cannot use. A dashboard does not need a traffic source. A redesign does not need a from-scratch offer if the page already has one.

When the user cannot answer, assume the smallest set that still picks a direction. Write each assumption as one line at the top of the work, then research.
